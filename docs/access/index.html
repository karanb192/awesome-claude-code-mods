What can a Claude Code mod access?

A Claude Code mod is a plugin whose JavaScript or TypeScript hooks run inside your session with your permissions; mods aren’t sandboxed. Its code reaches files, processes and the network only through the mods API, so a static scan can list the methods it calls and the events it hooks. In the current catalogue of 6,124 counted mods, 5,924 have reported footprints: 62.1% contain recorded methods classified as writing files, running processes or driving Claude, 9.5% include $.http.fetch, and 47.2% hook every tool call or every prompt with no filter recorded. 6.3% also reference methods the grader cannot classify yet. Check a mod’s page before you install it.

“Mod” here means a plugin with a hooks module. Plugins that carry only skills, settings hooks or MCP servers are not mods and are not in these numbers. Last full scan Oct 25, 2026 on Claude Code 2.1.310.

How does a mod get access?

Its hooks run inside your Claude Code session with your permissions, and mods aren’t sandboxed (Anthropic: what a mod can reach). To do anything outside its own code, such as drawing, reading a file, starting a process or making a request, a hook calls the mods API; it has no other way out (what a hook can do with an event). The events matter as much as the calls: a mod that hooks tool.call or prompt.submit sees the matching tool calls or prompts, all of them when the hook has no filter, and can change them (review what a mod can do).

That is why a static scan works: claude plugin validate reports the events each mod hooks and the API methods its code references, and this catalogue records both for every mod.

What do the four levels mean?

Each mod gets the widest level of the API methods it references. Levels order what a mod’s own code calls; they are not safety ratings and not limits on what a started program can do. Counts are reported footprints by classified calls.

How do I check a mod before installing it?

  1. Open its page from the collection.
  2. Read the level, any unclassified calls, the events it hooks and the validation result.
  3. Open the source at the scanned revision linked on the page.
  4. Or run claude plugin validate on the plugin yourself.

What the scan cannot tell you

  • It is a static scan, not a runtime test.
  • A program the mod starts with $.process.run reaches the network with your own access, and network policy for $.http.fetch does not cover it (Anthropic: which controls still apply). A tool call or prompt the mod rewrites changes what Claude does. Both can do more than the mod’s own calls show.
  • Unclassified methods have no grade.
  • Retained records show their last recorded footprint, not a current one.
  • Passing validation does not mean a mod is safe or works.
