What these mods do

Claude’s API caches a prompt prefix. When a request repeats a prefix that is already cached, the API reuses it at the cache read price; otherwise it processes the full prompt and caches the prefix. A hit needs an identical prefix, and a change earlier in the prompt invalidates what follows. By default an entry lives 5 minutes, or 1 hour with the extended option, and each use refreshes it at no extra cost. In API billing a cache write costs 1.25 or 2 times the base input price and a read 0.1 times on most models (Anthropic: how prompt caching works, pricing). Which lifetime a Claude Code session gets, and how it is billed, depends on the account and the setup; this page does not state it, and each mod’s README says what it assumes.

These mods do three jobs. A timer shows how long the entry has left and how much of the last request the cache served. A warmer sends a request that reuses the cached prefix before the entry lapses, so the entry is refreshed. A guard warns before a message that would be sent against a lapsed entry and shows an estimate of the write. Some compact or hand off a session while the entry is still live instead.

How to choose one

  • A warming request is a model request on your plan or API key (Anthropic: what a mod can reach). Read the mod’s README for how often it sends, for how long, and how to stop it.
  • Read the calls line on the mod’s page, and the README, for the job each call does. $.model.fork runs one completion over the session’s own transcript so the API serves that prefix from its cache; $.model.complete runs a completion with no history; $.prompt.submit submits a prompt as you. Any of them can belong to a warmer, a guard, a compaction tool or something else. A level does not tell you the job, and the job does not tell you the level. Of the 24 mods here named cache-clock or cache-timer, 24 have reported footprints; by classified calls, 3 at L0, 7 at L1, 13 at L2 and 1 at L3. Of the 251 mods here with reported footprints, 97 record a $.model method or $.prompt.submit; a recorded call does not identify a warmer.
  • Read the hooks line. A prompt.submit hook sees matching prompts, or every prompt when no filter is recorded (Anthropic: review what a mod can do). When the footprint is incomplete, event coverage is unknown. 102 of the 267 mods here record a prompt.submit hook, 9 of them with an incomplete footprint, where coverage is unknown.
  • Check which lifetime the mod assumes. The API offers 5 minutes and 1 hour; what your session gets depends on how it is billed, and the README says what the mod assumes.
  • The scan is static. It lists what the code references, not what it does at runtime. A level does not limit what a program the mod starts can do (Anthropic: which controls still apply). “Reads mod state” means the scan saw a state read and does not record whose state. See what a mod can access.
